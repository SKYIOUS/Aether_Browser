## Flags for the next slices

1. **D2-A COMPLETE:** `fetch_full_mock` was 2.28 s because `normalize_url`/`resolve_url` mangled `mock://` URLs into `https://mock://...` which missed mocks and hit real DNS timeouts (~270 ms × 10 lookups). Fixed: both functions pass through any URL containing `://`. Corrected baseline: ~10.5 ms (undelayed), ~109 ms (9 × 5 ms serial delays + pipeline overhead).

2. **First sync cold anomaly:** The very first `do_fetch_page_content_sync` call in a process takes ~4.5 s (small page) vs expected ~400 ms (font init + layout). Subsequent sync warms and all async calls are fast (5–15 ms). Root cause: one-time initialization in sync path (likely reqwest client or mock mutex spin-up). Not a steady-state issue.

3. **Large DOM bottleneck confirmed:** 5000 elements → 5–6 s consistently. Breakdown: ~3.5 s text measurement (5000 × 700 µs) + ~1.8 s Taffy layout. Extraction and parsing are minor. Optimization target: batch text measurement or avoid per-element wrapping.

4. **Parsing regressions** in HTML/CSS parsing (parse_html +262%, parse_css_2k_rules +133%) are unrelated to D2-A and need separate investigation.

5. **D1 concurrency validated:** Concurrent subresource fetching reduces warm multi-resource time from 368 ms → 178 ms (2.1×). Mock mutex contention limits theoretical maximum; real network would see larger gains.

6. **Paint instrumentation deployed (D3):** Cache hit/miss, per-component timing (geometry/text/image/box/form), culling stats, idle time, invalidation reasons (scroll/inspect/navigation/resize).

7. **C3 CSP redirect revalidation** already lands (C3 complete). Any new work must not regress the post-redirect CSP recheck.
