| Scenario | Cold (iter 1) | Warm (iter 2-3) | Taffy Floor | Hit Rate (cold→warm) | Notes |

**Key E3 findings:**
1. **8,192-entry cache is optimal** for realistic working sets (20k–27k unique keys)
2. **Taffy floor ~3.0 s** exposed at 5k elements when cache warm
3. **Numeric fast path works**: 56% of measurements on numeric-heavy page
4. **Deep DOM is fast**: 200 levels = 78 ms (Taffy floor ~76 ms)
5. **Normal pages fast**: 110 elements = 145 ms (Taffy floor ~145 ms)
6. **Parsing regressions FIXED**: HTML/CSS back to 2026-08-24 baseline

## Flags for the next slices

1. **D2-A COMPLETE:** `fetch_full_mock` was 2.28 s because `normalize_url`/`resolve_url` mangled `mock://` URLs into `https://mock://...` which missed mocks and hit real DNS timeouts (~270 ms × 10 lookups). Fixed: both functions pass through any URL containing `://`. Corrected baseline: ~7.5 ms (undelayed), ~108 ms (9 × 5 ms serial delays + pipeline overhead).

2. **E1–E3 COMPLETE — Layout bottleneck fully attributed:** 5k-element layout = 1.2 s. Breakdown: Taffy floor ~3.0 s when cache saturated, but with 8K cache + numeric fast path: 1.2 s median. Text measurement no longer dominant.

3. **Taffy floor exposed:** At 5k elements with full cache, Taffy + result application = ~3.0 s. This is the new optimization target.

4. **HTML/CSS parsing regressions FIXED:** parse_html/parse_css back to 2026-08-24 baseline (26–32% improvement).

5. **Numeric fast path effective:** 56% hit rate on numeric-heavy pages, 100% exact-match verification.

6. **Paint instrumentation (D3):** Cache hit/miss, per-component timing, culling stats, idle time, invalidation reasons.

7. **C3 CSP redirect revalidation** complete.
