# D0 Performance Baseline — 2026-08-24

Reference artifact for Phase D. These are **not pass/fail thresholds**; later slices (D1 async subresources, profiling work) compare against them under the same environment and must show meaningful, CI-consistent deltas rather than chasing any single number.

- **Commit:** parent of this commit (to be filled at commit time)
- **Toolchain:** rustc 1.97.1 (8bab26f4f 2026-07-14), stable, debug-profile benches
- **CPU:** AMD Ryzen 7 7735U with Radeon Graphics
- **OS:** Windows (local), `-j 2`
- **Command:** `cargo bench -j 2 --bench pipeline -- --warm-up-time 1`
- **Units:** median with Criterion 95% confidence interval; ns = nanoseconds, µs = microseconds, ms = milliseconds, s = seconds

## Flags for the next slices

1. **`fetch_full_mock` at 2.28 s is unexpectedly heavy** for one tiny mock document + 9 zero-latency subresources. D1's first job is to attribute that cost (suspects: JsBridge::load_dom, image-decode attempts, per-response filesystem writes) before parallelism can be measured.

2. **The delayed variant (9 × 5 ms serial sleep ≈ 45 ms) is statistically indistinguishable from the undelayed run** — buried under flag #1. Once that cost is understood/shrunk, the delayed bench becomes the serial-vs-parallel comparison for D1.

3. **`taffy_5k_wrapped` at 137 ms/frame** dwarfs everything else from Phases A–C; layout is the dominant profiling target; A2 culling does not help layout itself.

3. **C3 CSP redirect revalidation** already lands (C3 complete). Any new D0/D1 work must not regress the post-redirect CSP recheck.

## Reproducing

```
cargo bench -j 2 --bench pipeline -- --warm-up-time 1
```

Estimates land under `target/criterion/<group>/<bench>/new/estimates.json`.
