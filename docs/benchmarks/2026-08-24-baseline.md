### Key E0 Findings

1. **Cold varied text (realistic single-page load):** 25,000 measure calls → **0% cache hit** (512-entry LRU overflows) → 25,000 Buffer constructions → **17.8s shaping dominates 18s total**.

2. **Cache hit rate is the critical variable:** 0% hit → shaping dominates; 99.9%+ hit → Taffy dominates (293ms–3.8s).

3. **Root cause:** 512-entry LRU cache is catastrophically undersized. Each paragraph generates ~5 measure calls (for "M", " ", and each word during wrapping). 5,000 unique paragraphs → 25,000 unique keys → cache holds only 2% of working set.

4. **Taffy bottleneck when cached:** Even with perfect cache, Taffy + result application takes 293ms–3.8s for 5k elements. Anomaly: shared-text warm run 3.8s vs cold 1.6s needs investigation.

5. **FontSystem init:** 1 construction per process (~380ms one-time), not per-layout.

## Flags for the next slices

1. **D2-A COMPLETE:** `fetch_full_mock` was 2.28 s because `normalize_url`/`resolve_url` mangled `mock://` URLs into `https://mock://...` which missed mocks and hit real DNS timeouts (~270 ms × 10 lookups). Fixed: both functions pass through any URL containing `://`. Corrected baseline: ~10.5 ms (undelayed), ~109 ms (9 × 5 ms serial delays + pipeline overhead).

2. **First sync cold anomaly:** The very first `do_fetch_page_content_sync` call in a process takes ~4.5 s (small page) vs expected ~400 ms (font init + layout). Subsequent sync warms and all async calls are fast (5–15 ms). Root cause: one-time initialization in sync path (likely reqwest client or mock mutex spin-up). Not a steady-state issue.

3. **E0 COMPLETE — Large DOM bottleneck attributed:** 5000 elements → 18s layout (cold varied). Breakdown: **17.8s text shaping** (25,000 measure calls, 0% cache hit due to 512-entry LRU) + **0.2s Taffy**. Optimization target: **increase measurement cache capacity** or **avoid per-word measurement in wrap_text**.

4. **Taffy floor when cached:** Even with perfect cache, 5k elements → 293ms–3.8s Taffy+application. Anomaly: shared-text warm run 3.8s vs cold 1.6s needs investigation before E1.

5. **Parsing regressions** in HTML/CSS parsing (parse_html +262%, parse_css_2k_rules +133%) are unrelated to D2-A/E0 and need separate investigation.

6. **D1 concurrency validated:** Concurrent subresource fetching reduces warm multi-resource time from 368 ms → 178 ms (2.1×). Mock mutex contention limits theoretical maximum; real network would see larger gains.

7. **Paint instrumentation deployed (D3):** Cache hit/miss, per-component timing (geometry/text/image/box/form), culling stats, idle time, invalidation reasons (scroll/inspect/navigation/resize).

8. **C3 CSP redirect revalidation** already lands (C3 complete). Any new work must not regress the post-redirect CSP recheck.
